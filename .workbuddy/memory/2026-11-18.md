## MagicShell：布局记忆（0.4.0）

需求：把布局记住，下次运行自动加载。

现状核查：0.3.0 其实已经把 `rect` 和 `layout{key,custom}` 写进配置并在启动时还原（实测可行），
但有几个会让"记忆失效"的真坑，这一版都修了：

1. **主进程两个写入方互相覆盖**：窗口 resize/move 的 `saveBounds()` 与渲染进程的 `config:save`
   各自 `readConfig()` → 改 → `writeConfig()`，400ms 防抖窗口内后写者会用旧 groups 覆盖新布局。
   → 改成主进程内存单份 `configCache`：`readConfig()` 只读缓存，`patchConfig(patch)` 只合并指定字段，
   `config:save` 也只合并 settings/groups，window 永远不丢。
2. **写入非原子**：`writeFileSync` 写到一半被杀 → JSON 残缺 → `readConfig` 吃异常返回默认值 → 整个布局清零。
   → 先写 `.tmp` 再 `renameSync`，并保留 `magicshell-config.bak.json`，主文件坏掉自动回退（已实测：故意写坏主文件，能从备份恢复分组名与 rect）。
3. **窗口最大化状态没存**：用户最大化使用，重启后开成 1280×820，看着像"布局没记住"。
   → window 增加 `maximized`/`fullscreen`，用 `getNormalBounds()` 存还原尺寸，ready-to-show 时先 maximize 再 show；
   坐标用 `sanitizeBounds()` 校验是否还落在某块屏幕上（拔副屏/改分辨率），不在就交给系统居中。
4. **松手不立即落盘**：拖完只排 320ms 防抖，紧接着杀进程就丢。
   → `persist(immediate)`，拖动/缩放结束调 `persist(true)`；另加 `pagehide` + `visibilitychange` 兜底。
5. **排列下拉把"自定义"误标成"自动"**：custom=true 时 key 仍是 'auto'，下拉里 ✓ 打在"自动"上。
   → custom 时首项插入"自定义（手动摆放）"+ 用真实 rects 画的缩略图 + ✓；预设项不再打勾；
   底部增加说明行"布局会自动记住，下次启动按原样恢复"；"应用到全部分组"在 custom 下改为"所有分组改回自动排列"。
6. **恢复时个别终端缺 rect 会整组重排**：`syncGroupRects` 原来只要有一个无效就 applyLayoutRects 重置全部。
   → 只有"全都没有 rect"或非自定义布局时才整组重排；custom 且舞台可测量时，缺位置的用 `carveRectForNew()` 劈最大窗补位。
7. 启动恢复后右下角提示"已恢复上次布局 · N 个分组 / M 个终端"（`toast(msg, 3200)`，toast 增加时长参数）。

验证：
- 新增 `tools/e2e-persist.mjs`（stamp / verify 两段式，跨进程）：stamp 摆 4 窗自定义布局并 `persist(true)`，
  写期望值到 `.tmp/expected-layout.json`；关窗后用同一 user-data-dir 重启，verify 比对分组数/名称/layout.custom/
  每个 rect/DOM 百分比/磁盘配置/window 字段/activeId → 9/9。
- 开发版 + 打包版各跑一遍（打包版走 `window.close()` 真实关窗路径），另跑 e2e 9/9、e2e-input 7/7、e2e-look 10/10、e2e-layout 10/10。
- 损坏配置回退测试：手写非法 JSON 主文件 + 有效 .bak，启动后从备份恢复成功。

坑：
- e2e-persist 的 verify 必须紧接在 stamp 重启之后跑；中间插别的 e2e 会改状态导致 activeId/rects 对不上（第一次就是这样误报 4/9）。

## MagicShell：每个终端独立启动目录（0.5.0）

需求：能给每个 shell 指定默认路径吗？

实现：
1. 数据模型：`pane.meta.cwd`（该终端的启动目录，null=跟随全局）+ `pane.meta.liveCwd`（OSC 7 实时目录，不存盘）。
   `settings.startDir` 全局默认（null=用户主目录）、`settings.recentDirs` 最近 8 个（存盘）。
2. 主进程：`normalizeDir()`（去引号/展开 ~/相对路径按主目录/要求是存在的目录/path.resolve 统一反斜杠）；
   `pty:create` 目录优先级 pane > 全局 > 主目录，返回 `cwd/cwdFallback/requestedPath`，坏目录不再静默降级。
   新增 IPC `dir:pick`（dialog.showOpenDialog）、`dir:check`（纯校验，不弹窗）、`dir:home`。
3. 目录实时跟踪：shell 启动加 `-NoExit -EncodedCommand <base64(UTF-16LE)>` 注入 prompt 包装，
   调用原 prompt 并在前面拼 `ESC]7;file://HOST/C:/path BEL`；渲染层 `term.parser.registerOscHandler(7)` 接住。
   注意：prompt 里 `$ExecutionContext.SessionState.Path.ProviderPath` 是空的，必须用 `$PWD.ProviderPath`（踩过）。
   cmd.exe 不注入（没有对等钩子），liveCwd 为空时弹层显示「shell 还没报告」。
4. 会话 token：pty 消息带 `sid`，`restartPane` 杀掉旧进程后立刻重开时，旧进程迟到的 data/exit 会被丢弃。
5. UI：终端菜单「启动目录…」+「在此目录新开终端」；弹层 `#cwd` 有输入框/浏览/实时校验/当前所在目录「用这个」/最近使用 chips/恢复默认/保存/保存并重启；
   设置抽屉「默认启动目录」（浏览+清除）。`shortenPath()` 用于菜单 hint 与 chips。
6. `restartPane` 现在支持运行中的终端（kill → 等 180ms → respawn），用于「保存并重启」。

坑：
- addPane 原来在 `requestAnimationFrame` 里 ensureSpawn：窗口被遮挡/最小化时 rAF 被节流，新终端迟迟不启动（e2e 大面积误报）。
  改成直接 spawn、rAF 只负责 fitPane。
- e2e 里主进程按自己内存配置决定 cwd，改完 `settings.startDir` 必须先 `persist(true)` 再新建终端，否则用旧值。
- 相对路径/大小写/斜杠不同会导致 recentDirs 存重复：`addRecentDir` 与 chips 渲染统一过 `normDirPath` 再去重。

验证：新增 `tools/e2e-cwd.mjs` 12 项（默认主目录/全局默认/单终端重启生效/OSC 7 跟踪/恢复默认/坏目录回退+提示/落盘/菜单/对话框/保存+继承/设置抽屉/无异常），
开发版与打包版各 12/12；回归 e2e 9/9、e2e-input 7/7、e2e-look 10/10、e2e-layout 10/10、e2e-persist 3/3+9/9。
docs 增加 `screenshot-cwd.png`（docs-shots.mjs 现在支持端口参数并会截启动目录弹层）。

## MagicShell：目录历史 + 热键逐级回退（0.6.0）

需求：多次用 cd 更换当前目录后，可以用热键逐级回退。

实现（全在渲染层 `src/renderer/app.js`）：
1. `pane.hist = { list, idx, expect, from, timer }`：每终端一份目录栈，**只放内存不落盘**（doPersist 只挑固定字段）。
   `noteDirVisit()` 挂在 OSC 7 handler 里；`resetDirHistory()` 在 ensureSpawn 成功后调用，并用 `res.cwd` 作为新栈根。
2. `goToHistIndex(pane, i)`：设 idx → `expect=目标` → `sendCd()`（先发 Ctrl+C 再发 `cd "path"`，cmd 用 `cd /d`）。
   收到 expect 匹配的 OSC 7 就只保留指针、不重复记一条；1.6s 没匹配则回滚指针并 toast「没能切过去」。
3. 热键在 `onKeyDown` 最前面（Alt+←/→/↑），焦点在 input/textarea 时不抢（xterm 的 `.xterm-helper-textarea` 例外）。
   Alt+↑ 直接发 `cd ..`，上级路径只用于提示。
4. 菜单：`openPaneMenu` 加「回到上一级目录 / 目录历史后退 / 目录历史前进」+ `renderDirHistList()` 列表（当前项 ●，点哪条跳哪条）。
   `openMenu` 新增 `disabled` / `title` 支持；`.ctx-menu` 加 max-height + 滚动。

坑（都踩过）：
- 跳转期间的 Ctrl+C 会让 shell 重画旧 prompt，先来一条旧目录的 OSC 7。原逻辑「mismatch 就清 expect」导致这次跳转被当成用户换目录、重复入栈。正解：expect 未匹配期间一律 return，等匹配或超时。
- `renderDirHistList` 的 `to` 用了 `min(len, idx+4)`，越界渲染出一行空路径；应为 `min(len-1, idx+4)`。
- 测试里 Alt+↑ 之后 list 会截断前进记录（[root,sub,deep] → [root,sub,root]），预期值别按「追加」算。

验证：新增 `tools/e2e-hist.mjs` 14 项（起始记录/cd 累积/Alt+←×3/Alt+→/Alt+↑/菜单列表与禁用态/点选跳转/中途换目录截断/坏目录回滚/重启清空/输入框不抢热键/无异常），开发版与打包版各 14/14；回归 9/9、7/7、10/10、10/10、12/12、persist 3/3+9/9。
docs 增加 `screenshot-history.png`（docs-shots.mjs 新增一段：临时分组 + 连 cd 三次 + cls + 打开菜单 + 截图后关掉该分组）。

## MagicShell：侧边栏收起 / 展开 + 拖宽（0.7.0）

需求：左侧的侧边栏应该可以收起和展开并且可以调节宽度。

实现：

## MagicShell：窗口重叠时"点不到/穿透/激活即失活"（0.7.1）

现象（用户报）：分组-01 里白底终端激活后立即失活、拖不动、鼠标在标题栏不变手形、点击穿透到后面的终端。

根因（**CSS 层叠上下文逃逸**，不是事件逻辑）：
- `.pane-slot` 只有 `position:absolute` + `z-index:auto` → **不建立层叠上下文**；
- `.pane` 同理（position:relative + z-index:auto），于是 xterm 内部的 `xterm-link-layer z=2`、`xterm-helpers z=5`、
  `composition-view z=1` 这些**正 z-index 后代会逃到舞台层**，压过相邻 `.pane`（它们都在 z=0 层）；
- `.pane-head` 是 `position:static`，`z-index` 根本不生效 → 标题栏被别人的画布盖住。
- 于是：视觉上是 A 窗，命中的是 B 窗的 canvas → 光标不是 grab、点下去激活了 B、A "立即失活"、拖不动。
- 只有当两个窗矩形**重叠**时才暴露，所以之前所有用例（分屏不重叠）都没抓到。

修复（3 处 CSS + 2 处 JS）：
1. `.pane-slot { z-index: 1 }` —— 显式值建立层叠上下文，锁住 xterm 内部的 z-index。
2. `.pane-slot.focused { z-index: 2 }` / `.pane-slot.dragging { z-index: 3 }` + `setFocusedPane` 同步 slot 的 focused 类、
   `startPaneDrag` 加/去 slot 的 dragging 类 —— 实现"点哪个哪个浮到最前"。
3. `.pane-head { position: relative; z-index: 6 }` —— 压过 xterm helpers(5)，低于 grip(8)。
4. 删掉 `.pane.dragging { z-index:4 }`（slot 建上下文后它只在内部生效，改由 slot 承担）。

验证：新增 `tools/e2e-stack.mjs` 12 项（槽位有显式 z / 标题栏 positioned 且 >5 / 压接缝的窗标题栏命中自己 / 光标 grab /
点击后唯一焦点且原焦点失活 / 激活槽位置顶 / 重叠区命中视觉最上层 / 拖标题栏能移动 / 拖动中 z=3 松手回落 /
从可见区切换焦点 / 退出遮罩没被画布盖住 / 无异常）。开发版 12/12。
回归：9/9、7/7、10/10、10/10、12/12、12/12(cwd)、14/14(hist)、persist 3/3+9/9。
坑：用例里**不要用 requestAnimationFrame 等待**——窗口被遮挡时 rAF 被节流，用例会挂到超时；改 setTimeout。
另：`createGroup()` 默认自带一个终端，测试里别再 addPane 三次（会多出一个全屏窗，把所有断言带偏）。

版本 0.7.1。README 补了"窗口可重叠、点哪个哪个置顶"与一条限制（完全被盖住的终端要拖开上面那个）。

## MagicShell：点标题栏激活后要拿到输入焦点（0.7.2）

现象（用户报）：点标题栏激活某个 shell 时，这个 shell 应该自动获得输入焦点（视觉高亮有了，键盘打不进字）。

根因：**浏览器 mousedown 的默认动作**。`.pane-head` 等区域不可聚焦，mousedown 后浏览器把焦点交给 `body`；
我们的 handler 在 mousedown 里 `term.focus()`，紧接着默认动作又把它抢走 → 只剩高亮，没有输入焦点。
（点终端正文没问题，是因为 xterm 自己的 mousedown handler 会 preventDefault 并 focus textarea。）

修复：
1. `el` 的 mousedown：目标不在 `.xterm` / `.pane-title-input` 时 `e.preventDefault()` + `focusPane(pane.id)`；
   在 `.xterm` 里只 `setFocusedPane`（xterm 自己会聚焦，别破坏它的选区行为）。
2. 缩放手柄的 pointerdown 已经 preventDefault（会连带压掉 mousedown），所以那里显式补一次 `focusPane`。
3. 侧栏点分组：`activateGroup()` 之后加 `focusActivePane()`；顺手把 `focusActivePane` 改成走 `focusPane`
   （原来只 `term.focus()`，视觉高亮不同步）。
4. 菜单：`openMenu(x, y, items, restoreFocus)` 加第 4 参（终端 = 还给它；true = 还给当前终端），
   在**菜单容器**上挂一次冒泡 click → `restorePaneFocus()`。挂容器而不是挂每个按钮，是因为布局缩略图/色块/目录历史
   这些 `render()` 自定义项走的是自己的 click handler（第一版只改了普通项，布局菜单就这么漏了）。
5. `restorePaneFocus(pane)`：`setTimeout(0)` 后检查 `document.activeElement`，若是 INPUT/TEXTAREA/对话框就先别抢
   （改名、启动目录、外观面板要能正常输入）。

验证：新增 `tools/e2e-focus.mjs` 13 项（点正文/点标题栏互换焦点/点完标题栏直接打字进该终端/双击改名回车后焦点回终端/
拖标题栏移动后/拖边框缩放后/布局菜单/「更多」菜单/侧栏切组/退出遮罩「重新启动」/无异常），开发版与打包版各 13/13；
回归 9/9、7/7、10/10、10/10、12/12、14/14、12/12、12/12（开发版+打包版各跑一遍）。

坑：**测这个必须用 CDP 的 `Input.dispatchMouseEvent`（真实事件）**。`el.dispatchEvent(new MouseEvent('mousedown'))`
是 untrusted 事件，浏览器不执行默认动作，测出来永远是"PASS"（第一版用 dispatchEvent 复现不出来）。
键盘同理用 `Input.dispatchKeyEvent`（`type:'keyDown'` 带 `text` 字段才会产生字符）。读 buffer 别只取最后 N 行——
xterm 的 buffer 后面可能全是空行，要全量扫。

## MagicShell：中英双语（0.8.0）

需求：支持国际化。评估后选定「全量中英双语」——不是只做骨架，而是把界面文案全量抽成 key + 加一条"英文界面零中文残留"的自动断言。

实现：
1. `src/shared/i18n.js`（UMD，主进程 `require` 与渲染层 `<script>` 共用一份字典）：zh-CN / en-US 各 212 条 key，
   按区域分组（app / group / toolbar / sidebar / pane / menu.* / layout / palette / hist / drawer / look / cwd / boot / main）。
   API：`t(key, vars)`（`{name}` 占位）、`has`、`setLocale`、`getLocale`、`resolveLocale`、`onChange`、`missingKeys`。
   **值可以是函数**（`(v)=>v.n===1?'1 terminal':v.n+' terminals'`），英文单复数不用写分支。
2. `resolveLocale(setting, systemLocale)`：`auto` 时 `zh-*`→zh-CN、`en-*`→en-US、其它→en-US（非中文 Windows 别硬塞中文）。
   `setLocale` 同步 `document.documentElement.lang` 并通知订阅者；缺 key 时 warn 并回退中文。
3. 静态文案走属性：`data-i18n` / `data-i18n-title` / `data-i18n-aria` / `data-i18n-ph`，`applyI18nDom(root)` 一把刷。
   index.html 里 62 处挂属性（保留原中文当默认值，JS 没加载时界面也不会空）。

## MagicShell：命令块 / Shell Integration（0.9.0）

需求：用户问"还有什么更酷的功能可以加"，评估后选了「Shell Integration 包」——命令块标记（成功绿/失败红）+ 耗时 + Ctrl+↑↓ 跳命令 + 跑完通知。

关键判断：**不用新写 shell 交互**。之前为了 OSC 7（实时目录）已经注入了 prompt 包装，
在同一个钩子里多发几个 OSC 133 序列（Windows Terminal / VS Code 同款）就够了：
```
133;D;<退出码>  上一条命令结束  133;A 提示符开始  133;B 提示符结束
```

实现：
1. `main.js`：`CWD_HOOK_PS` 改名 `OSC_HOOK_PS`，在返回提示符前拼 D + A + OSC7，之后拼 B。
2. 渲染层 `app.js` 新增「命令块」一节：
   - `noteCommandRun(pane)`：`term.onData` 收到 `\r` 时 `registerMarker(0)` + 记 `performance.now()`；
   - `finishCommand(pane, exit)`：收到 `D` 收尾成 `{marker, exit, ms, text}`，压进 `pane.cmd.blocks`（上限 400，超了 dispose 老 marker）；
   - `renderCmdBadge`：标题栏右侧 `✓ 717ms` / `✗ 1 · 0.11s`；**成功且 <300ms 不显示**，避免刷屏；
   - `jumpCommand(±1)`：以"视野基准行"（到底=cursor 行，翻上去=viewportY）找上/下一条，`scrollToLine` + 闪一下；
   - `copyCommandOutput`：marker 到下一条 marker 之间取行，**末尾那行"下一个提示符"用 `promptText` 比对裁掉**；
   - `shouldNotify(ms,{focused})`：超过 3s + 窗口不在前台 + 开关打开 → `api.notifyDone`（主进程 flashFrame + Notification）；
     跑超 3s 时 `api.setProgress(2)` 挂不确定进度条，收尾 `-1`。
3. 主进程新增 `win:progress` / `notify:done` 两个 IPC（`Notification` 需从 electron 引入）。
4. 设置抽屉加「命令跑完提醒」开关（`settings.notifyOnDone`），i18n 182→228 条。

退出码怎么拿（这是最容易错的地方）：
- `$?` 为真 → 0；
- 为假时优先用 `$LASTEXITCODE`，但 **cmdlet 报错不会更新它**，会读到上一条原生命令的旧值。
  用 `$global:__msLastCode` 记住上次看到的 `$LASTEXITCODE`，一样就当成陈旧 → 记 1。
  实测：`echo hi`(0) / `Get-Item C:\nope`(1) / `cmd /c exit 3`(3) / `echo ok2`(0) / `Write-Error`(1) 全对。
  已知边角：连续两次同一条原生命令、退出码又相同，第二次会记成 1（状态对，数字不精确），写进 README 限制。

坑（都踩了）：
- **`registerDecoration` 是 proposed API**，不设 `allowProposedApi: true` 会直接抛错，
  而我第一版把它包在 try/catch 里 → 闪烁功能"静默不生效"，白查半天。现在 Terminal 构造里显式打开（xterm 版本钉死的）。
- **decoration 的 backgroundColor 不吃 rgba 透明度**：写 `rgba(...,0.22)` 会渲染成整行高饱和蓝条，把文字冲掉。
  正解是按主题 `mix(bg, accent, 0.24)` 预混一个实色再传进去。
- **`term.input()` 不会触发 `onData`**（命令会执行，但 `noteCommandRun` 不跑）→ 所以 docs 截图和用例都必须用
  CDP 的 `Input.insertText` + `Input.dispatchKeyEvent`；docs-shots 里还得先 `Page.bringToFront`，否则窗口不在前台时输入会静默丢失。
- **空回车判定不能靠"这行是不是空的"**：提示符本身就在这一行。要在 `133;B` 时把提示符文本记下来（`cmd.promptText`），
  回车时 `line.startsWith(prompt) ? line.slice(prompt.length)` 看剩下的是不是空。
- 用例要**自愈**：`settings.shell` 上一轮被改成 cmd 后残留，会让下一轮整片失败（第一版就 4/17）。
  setup 里显式 `settings.shell = 'auto'` + `persist(true)`。
- e2e-cmd 里取 pane 用 `groups.find(...).panes[0].id` 再过 `paneMap`，别拿 group id 去查 paneMap（会 undefined.panes）。

慢命令绿徽标 / 快命令不显示 / tooltip / 长输出仍记块 / Ctrl+↑ 两次 / Ctrl+↓ 回底 / 复制单条输出正好 40 行不含提示符 /

## 终端可停止 / 按组启停（0.10.0）

需求：恢复一堆分组时，每个终端背后都是一个常驻 pwsh（实测每个 100MB 工作集 / 34MB 私有），
希望「关掉 shell 但保留窗口」，并在侧栏组名上按一下批量启动。

实现要点：
- `meta.suspended` 做成一等状态（写进配置），与懒加载的「未启动」分开记；`ensureSpawn(pane, {force})`
  遇 suspended 直接返回，`activateGroup` 只补非 suspended 的 —— 否则切一次组就自动复活，功能白做。
- `stopPane`：杀 PTY、`resetCmdState`（否则留下一条计时中的假命令块）、记 `resumeCwd = liveCwd`；
  `startPane`：用 resumeCwd 作 cwd，`term.reset()` 后 force spawn。
- `pty:exit` 处理器加 `if (pane.meta.suspended) return`，否则主动 kill 会被渲染成「终端已退出」。
- 侧栏组行加 `.group-power`：全运行=停止整组，否则=启动整组（启动时顺带切组、错开 120ms）；
  徽标改成 `运行/总数`。`renderSidebar` 会重建 DOM，用例读状态前必须重新取节点。
- 停止态用顶部窄横幅 `.pane-stopped`（不是整块遮罩），输出仍可看；`.pane.stopped .pane-body`
  加 36px 上内边距，否则横幅会压住最上面一行输出。
- 停止的终端里打字 = 自动启动并把首键写入（`term.onData` → `startPane({firstData})`）。
- 主进程新增只读 `pty:stats`，用例用它断言「进程真的被回收」；`did-start-loading` 时清空 sessions，
  避免 Ctrl+R 重载留下孤儿 PowerShell（渲染层 beforeunload 发 kill 来不及，页面先没了）。

验证：新增 `tools/e2e-pause.mjs` 16 项；开发版与打包版各 144 项 + persist 3+9 全绿；版本 0.10.0。
